# Web 端 V1 产品需求文档（PRD）

状态：评审中
最后更新：2026-11-05

## 一、版本目标

验证"数字生态缸"核心假设：用户是否愿意长期打开并照看一个真实模拟的鱼缸。

- 平台：Web 端（桌面浏览器，优先 Chromium），支持窗口常驻与全屏观赏。
- 验证指标（上线后 4 周）：
  - 次日留存 ≥ 35%，7 日留存 ≥ 15%；
  - 人均单次时长 ≥ 8 分钟；
  - 核心动作渗透率：喂食 ≥ 90%，换水 ≥ 60%，装备调整 ≥ 40%。

## 二、核心循环

```
开缸（基础装备就位）→ 养水（硝化系统建立）→ 放鱼
   → 日常照看（喂食/观察/换水/调装备）
   → 水质与鱼状态变化 → 装备升级/造景 → 新鱼与新内容
```

情绪目标：每一次打开都有"它还好好地活着"的安定感，而不是待办清单式的压力。

## 三、V1 功能范围（In Scope）

### 1. 鱼缸场景

- 单个淡水缸，固定主视角，支持轻微视角摆动与缩放观赏；
- 基础视觉元素：水体、底砂、水面光影、气泡、鱼的实时游动；
- 桌面模式：窗口化常驻；全屏模式：屏保化观赏，隐藏操作 UI。

### 2. 生态模拟引擎

- 氮循环：氨氮（NH3）→ 亚硝酸盐（NO2）→ 硝酸盐（NO3），硝化细菌随滤材与时间建立；
- 水质参数：pH、温度、溶氧量、洁净度；
- 参数间存在因果联动（如过滤不足→氨氮升高→鱼压力/疾病；灯照过强过久→爆藻）；
- 时间模型：支持离线期间生态按压缩时间推演，回归后给出可读的"期间发生了什么"。

### 3. 生物

- 5-8 种入门淡水鱼（如孔雀鱼、红绿灯、斑马鱼、米奇鱼、神仙鱼等，最终清单在设计阶段确定）；
- 鱼的状态：饥饿度、压力、健康、成长、寿命；行为随状态变化（群游、躲藏、上浮、厌食）；
- 基础混养兼容性规则，不兼容组合在购买前给出温和提示；
- V1 不做繁殖系统，仅保留成长与状态表现。

### 4. 装备系统（V1 基础线）

| 装备 | V1 作用 |
|---|---|
| 过滤器（含滤材） | 决定硝化能力与水质净化速率 |
| 灯具（可调亮度/节律） | 影响观赏、藻类与昼夜节律 |
| 加热棒（可调温度） | 维持水温，偏离适宜区间影响鱼健康 |
| 喂食 | 手动喂食，食物残余影响水质 |
| 换水工具 | 手动部分换水，降低硝酸盐与污染 |

装备通过商城/装备面板获取与调节，每件装备参数真实作用于模拟引擎。

### 5. 信息与引导

- 水质面板：展示参数与状态灯（正常/警告/危险），不强制用户理解专业数值；
- 事件提示：鱼的异常、水质危险、装备失效以非打断式消息呈现；
- 新手引导：开缸 → 养水 → 放第一条鱼 → 第一次喂食/换水，10 分钟内完成。

## 四、V1 不做（Out of Scope）

- 繁殖与选育、稀有变种、图鉴成就体系（V2）；
- 水草种植、CO2 系统、复杂造景拖拽（V2，V1 仅预置底砂与简单装饰）；
- 海水缸、蛋分、造浪等海水线（V3+）；
- 小程序端、社交/参观、账号体系深度功能（V1 可用本地存档+轻账号）；
- 寻宝迷你游戏、助眠音频模式（后续版本）；
- 付费体系深度设计（V1 先验证留存，仅预留装备付费点埋点）。

## 五、关键用户故事

- 作为办公用户，我希望打开网页就能看到一缸游动的鱼，不需要学习任何操作。
- 作为办公用户，我希望工作时把它放在屏幕一角，鱼不会因为我忙碌就轻易死亡。
- 作为休闲用户，我希望换水、喂食是简单且有反馈的动作，做错了有提示而不是惩罚。
- 作为水族爱好者，我希望更换过滤器和加热棒后，能看到水质和鱼状态的真实变化。
- 作为回归用户，我希望离线回来后快速知道缸里发生了什么，而不是面对一堆数值。

## 六、非功能需求

- 性能：常规办公笔记本（集显）稳定运行，目标 30 FPS 以上，后台标签页自动降帧；
- 兼容：Chrome/Edge 最新两个大版本，响应式适配主流桌面分辨率；
- 存档：本地自动存档，支持数据导出，防止刷新丢失；
- 可观测：埋点覆盖核心动作、留存路径与参数异常，供 V1 验证使用。

## 七、待决问题（进入设计/架构阶段确认）

2. 模拟引擎的 tick 粒度与离线推演公式；
3. V1 鱼类与装备的最终数值表；
4. 轻账号与本地存档的边界。

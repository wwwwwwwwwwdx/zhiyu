# 产品需求 Backlog（V2 及后续）

状态：评审中
最后更新：2026-11-05

## 背景

本清单记录在 V2 繁殖选育完成后，通过对真实水族场景的提问与代码走查发现的需求。它们不属于 V1 PRD 范围，统一在此登记、评估优先级与依赖，避免在迭代中遗漏或无序插入。

判断原则：

- 以"放松、陪伴、不做任务感"为调性约束，凡是需要玩家刷清单、完成指定任务的设计都要谨慎；
- 优先做当前可验证、低风险、高感知的项；依赖真实数据或真实支付环境的项后置；
- 尊重现有分层：引擎零 DOM、可单测；位置等表现数据不写入存档。

## 需求清单

### B1. 鱼游动方式差异化（高优先级）

- **现状**：渲染层所有鱼共用同一 `sin/cos` 固定椭圆轨迹，仅相位不同，速度随行为变化；无自主转向、无群游、无鱼种差异、鱼会穿模。引擎不存位置。
- **真实情况**：灯鱼中层整齐群游、神仙鱼优雅缓慢且垂直上下游动、鳉鱼偏上层灵动、底栖鱼贴底觅食。
- **价值**：鱼游动是用户每天直接感知的核心，固定轨迹偏机械，直接削弱生命感与放松效果。
- **方案**：分两步——先做鱼种差异化（水层偏好、速度、振幅、边界避障），再做 boids 群游（分离/对齐/聚合）。
- **架构约束**：游动数学做成纯 TS 模块可单测；位置不写入存档，每次重新生成；不引入新依赖。
- **依赖**：与 B4 缸形状存在边界耦合，建议先在当前长方缸内完成，再随缸形状扩展。

### B2. 稀有鱼的特殊获取（中高优先级，已完成）

- **现状**：仅有"金币购买"一种获取路径。
- **真实情况**：稀有来自野生/人工、变异品系、选育提纯、特定渠道。
- **价值**：提供长线惊喜与收集深度，与繁殖、图鉴天然衔接。
- **方案**：让稀有鱼自然涌现——繁殖中低概率出现变异品系，或随机"游来一条特别的鱼"；不做任务解锁。
- **风险**：若做成"完成任务解锁"会重新引入做任务感，明确排除。
- **依赖**：依托已完成的繁殖系统；图鉴（V2 待做）可作为展示载体。

### B3. 鱼缸放置环境（中优先级，已完成）

- **现状**：背景为纯色清透浅青，无环境/位置概念。
- **真实情况**：多放客厅柜、玄关、书房、办公桌；讲究避开阳光直射（防爆藻）、避开空调/门口（温差）、靠近电源、承重足够。
- **价值**：强化"我的角落"归属感，并可与现有爆藻、温度系统因果联动。
- **方案（已落地）**：新增引擎层 `balance/environments.ts`，提供 4 个环境（书房桌面、客厅柜、阳光窗台、玄关），渲染层按配置生成背景墙、柜/桌面与窗户；环境选择持久化（存档升 v7）。
- **因果联动**：阳光窗台带 0.35 环境光暴露，关灯时也会在高 NO3 下缓慢促藻；温度联动暂不做，避免范围蔓延。不扩成房间装修游戏。

### B4. 鱼缸形状多样化（低优先级，已完成）

- **现状**：缸为写死的单一长方体，水体、底砂尺寸配套写死。
- **真实情况**：长方、正方、圆柱、弧形子弹头、异形、壁挂、茶几缸等；水面面积影响溶氧、水体大小影响稳定性、圆柱缸有视角畸变。
- **价值**：个性化与真实物理差异，但单独做接近换皮肤。
- **方案（已落地）**：新增引擎层 `balance/tankShapes.ts`，把缸规格数据化，第一版支持长方、正方、圆柱三种；渲染层按参数生成玻璃、水、底砂，游动边界随形状变化（圆柱为径向约束），气泡与水草位置同步适配。
- **物理差异**：小缸（正方/圆柱）水体小、容量由 60 降到 42；切换时若现有鱼装不下会被引擎拒绝。弧形/异形/壁挂/茶几缸不做，圆柱真实光学折射畸变作为已知限制未模拟。

## 优先级与执行顺序

| 优先级 | 需求 | 主要理由 |
|---|---|---|
| 高 | B1 鱼游动差异化 | 观感最大短板，纯表现层、低风险、无新依赖 |
| 中高 | B2 稀有鱼自然涌现 | 长线惊喜，依托繁殖系统，需避免任务化 |
| 中 | B3 放置环境 | 轻量氛围，可与爆藻/温度因果联动 |
| 低 | B4 缸形状 | 与 B1 耦合，待游动边界改造后再做 |

执行决策：先按 B1 → B2 → B3 → B4 推进；V2 原计划剩余的图鉴与成就、装备付费点，因图鉴易踩任务感、付费点暂无真实支付环境可验证，一并后置，待有真实数据或支付环境时再启动。

进度：B1-B4 全部完成。B1 鱼游动差异化；B2 稀有品系变异与遗传（v6）；B3 放置环境与窗台环境光促藻（v7）；B4 鱼缸形状多样化、游动边界随形状（v8）。

# 自制 glTF 资产规范（鱼与场景）

状态：评审中
最后更新：2026-11-05
适用范围：M2 自制 glTF 建模（Blender 等），约束模型在 Three.js 中的尺寸、朝向、命名、材质与导出，保证产出后可直接接入、无需返工。

## 一、坐标系与单位

- glTF 2.0 标准：右手坐标系、长度单位为米；Three.js 加载后与引擎场景单位一致。
- Blender 导出 glTF 时由导出器完成 Z-up → glTF Y-up 的转换，**不要在建模时手动旋转物体去适配**，保持物体本身应用过旋转（rotation 已归零）。
- 建模单位建议直接按"米"理解，与下方目标尺寸对齐。

## 二、前向朝向（关键）

- 鱼的**前向（嘴的方向）统一为 +X 轴**，鱼体水平、左右对称于 X 轴，背部朝 +Y、腹部朝 -Y。
- 依据：渲染游动逻辑中位置参数方程为 `x=sin(t), z=cos(t)`，在 `t=0` 时运动速度方向为 +X，且 `rotation.y=-t` 在 `t=0` 为 0，因此模型在无额外旋转时前向必须是 +X 才能与运动方向一致。
- 已知占位问题：M1 锥体占位用 `rotation.z=PI/2`，实际尖头朝 -X（倒着游），低模不可见；正式模型按 +X 前向制作后，接入时不再做 `rotation.z` 处理。

## 三、原点与尺寸

- 模型原点（pivot）放在**鱼体几何中心**，便于围绕中心做转向与摆尾。
- 目标体长（吻端到尾鳍末端）约 **0.6 个场景单位**，与现有占位（Cone 长 0.6–0.7）一致；不同鱼种可在 0.5–0.9 之间按成年体重比例微调。
- 模型整体居中于原点，避免加载后出现位置偏移。

## 四、层级与命名

- 根节点命名与 catalog id 一致，如 `guppy`、`neon`、`angelfish`；多部件用层级表达：
  - `guppy`（根）
    - `guppy_body`
    - `guppy_tail`
    - `guppy_eye_L / guppy_eye_R`
- 节点、网格、材质全部使用小写英文与连字符/下划线，不使用中文与空格，方便程序化查找。
- 材质命名 `<对象>_mat`，如 `guppy_body_mat`。

## 五、材质（PBR）

- 使用 glTF 标准 metallic-roughness 工作流：
  - 鱼体以非金属为主，`metallic` 建议 0–0.1，`roughness` 0.4–0.7（体表微润可偏低）；
  - 眼睛可用稍高 gloss（roughness 0.1–0.2）；
- 贴图（如需要）使用 2 的幂尺寸，优先 256/512，控制内存；透明纹理用带 alpha 的 PNG 并在材质中开启 alpha mode。
- 颜色基调可参考 catalog 鱼种的真实配色，保持同场景风格统一。

## 六、动画约定

- 优先骨骼（skinned）或分层节点动画：摆尾、胸鳍摆动为循环动画，循环名 `swim`；
- 非循环动作（如受惊冲刺）预留但 M2 可先不做；
- 动画在 Blender 中以 24/30 fps 制作，导出后由 Three.js `AnimationClip` 按名称取用；M2 首版可先静态模型，摆尾动画作为增强项。

## 七、导出设置（Blender）

- 格式选 glTF 2.0，优先 `.glb`（单文件、含贴图）或 `.gltf + bin + textures`；
- 勾选：应用修改器、Y-up 转换、动画（如含）；不勾选相机/灯光（场景灯光由渲染器统一管理）；
- Draco 压缩可用于减小体积，但需确认加载端引入对应 decoder，M2 前期先不启用。

## 八、文件组织

- 资产放入 `public/models/fish/`，文件名与 catalog id 一致，如 `public/models/fish/guppy.glb`；
- 通过相对 URL `/models/fish/guppy.glb` 由 `Renderer.setFishAsset` 加载。

## 九、交付前验证清单

1. 加载后无控制台错误，原点居中、前向朝 +X、体长约 0.6；
2. 沿游动路径运动时鱼头朝向运动方向，无反向或侧翻；
3. 多实例克隆互不影响，材质/贴图正常；
4. 断开或缺失文件时渲染器走降级逻辑，不白屏；
5. 内存：贴图与几何体尺寸在预算内，卸载时可被 dispose 释放。

# 渲染路线定档：Three.js vs 2D Canvas

状态：评审中
最后更新：2026-11-05

## 一、方案对比

| 维度 | Three.js（WebGL 3D） | 2D Canvas（风格化） |
|---|---|---|
| 真实感/沉浸感 | 强：体积光、焦散、水体折射、鱼的立体游动 | 弱：依赖插画风格，真实生态卖点表达不足 |
| 与产品定位匹配 | 匹配"真实生态引擎"差异化 | 更像桌宠挂件，撞现有浅度产品 |
| 资产成本 | 中：需要 glTF 鱼模型，可用程序化几何体过渡 | 低： sprite/序列帧即可 |
| 性能（集显办公本） | 固定小场景可控，需主动优化 | 天然轻量 |
| 包体 | three 约 150-200KB（gzip，按需导入） | 近乎零成本 |
| 扩展（海水缸/造景/寻宝） | 平滑支持 | 深度受限，后期大概率重构 |
| 开发复杂度 | 高：shader、光照、动画、插值 | 低 |

## 二、决策

**定档 Three.js，裸用 + 固定视角小场景，渲染层与引擎严格解耦。**

理由：
1. 产品的差异化空位是"真实"，2D 风格化会把产品拉回现有浅度桌宠的竞争带；
2. 鱼缸是**固定视角、封闭小场景、实体数量有限**，恰好是 WebGL 最容易控住性能的形态，不需要开放世界级渲染能力；
3. 资产可渐进：M0/M1 用程序化几何体与低模 glTF，验证玩法后再投入高精度模型；
4. 解耦设计保证低性能设备可走降级渲染器，而非重写引擎。

## 三、渲染层设计

### 场景组成

- 缸体：玻璃材质（透射/反射）、缸框、底砂；
- 水体：折射/吸收色调、漂浮微粒、气泡粒子（InstancedMesh/Points）；
- 光照：主灯模拟装备灯具，支持色温/亮度/昼夜节律动画，水面焦散（caustics）投射到底砂；
- 鱼：glTF 模型 + 骨骼/顶点动画，游动路径由 engine 行为数据驱动，渲染层做平滑插值与转向；
- 后期：轻度 bloom 与色调映射，默认关闭重开销效果。

### 渲染循环

- requestAnimationFrame 驱动；逻辑固定步长由累加器推进，渲染帧对逻辑状态做插值；
- 页面不可见（VisibilityChange）时暂停渲染、引擎按离线策略处理；
- 后台标签/窗口化时提供帧率档位（如 30/60）与分辨率缩放。

### 性能策略

- 鱼与气泡优先 InstancedMesh / 合并几何体，控制 draw call；
- 阴影仅一盏主灯、低分辨率贴图；反射用简化平面反射而非实时环境反射；
- 像素比上限 `devicePixelRatio ≤ 2`，提供画质档位（高/中/低）；
- 目标：集显办公本 1080p 下 30 FPS+，高端设备 60 FPS。

## 四、降级路径

- 启动时做 WebGL 能力探测与基准帧测试，不达标自动进入中档/低档；
- 低档：关闭后期、降低像素比与粒子数、简化水体；
- 完全不支持 WebGL 时给出提示页（V1 不实现 2D 渲染器，仅保留接口位）。

## 五、M0 Spike 验收标准

1. 浏览器中出现一个带玻璃缸、水体、底砂、灯光的场景；
2. 3 条低模鱼按 engine 输出的路径游动，行为与状态联动（如水质差时游动异常可见）；
3. 集显设备稳定 30 FPS，切换标签页自动暂停；
4. 渲染代码不包含任何生态计算逻辑，全部状态来自 engine 快照。

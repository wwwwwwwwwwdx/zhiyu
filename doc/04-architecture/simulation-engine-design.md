# 模拟引擎设计

状态：评审中
最后更新：2026-11-05

## 一、时间模型

### 固定步长 + 累加器

- 逻辑步长 `TICK = 1` 游戏秒；渲染帧之间用累加器消费固定步长，保证数值积分确定、可复现、可单测。
- 游戏时钟：`gameTime += TICK * TIME_SCALE`。`TIME_SCALE` 为时间压缩比（V1 建议默认 60，即现实 1 秒 ≈ 游戏 1 分钟），不同活动可配不同档位（观赏/养水/等待）。
- 渲染层对相邻两个逻辑状态做插值，鱼的位置与动画不出现跳变。

### 离线推演

- 关闭时记录 `lastSavedGameTime`；回归时计算离线游戏时长，超过阈值走**批量推演**（大步长数值积分 + 关键事件抽样），而非逐 tick 重放。
- 产出：终态快照 + 期间事件摘要（如"硝化系统已建立""硝酸盐偏高，建议换水"），控制在用户一屏可读。
- 防死亡设计：离线期间的惩罚温和化处理，避免用户因忙碌回来面对死鱼，符合解压调性。

## 二、实体与组件

轻量 Entity 模型，不引入 ECS 库：

```
World
 ├── entities: Entity[]
 ├── components: 按类型聚合的组件表（位置/生物/水质/装备…）
 ├── systems: 按固定顺序执行的系统函数
 └── eventBus: 领域事件
```

系统执行顺序（每 tick）：
`装备系统 → 化学反应（水质/氮循环）→ 生物行为与状态 → 事件收集 → 快照`

## 三、氮循环与水质模型（V1 核心）

### 状态变量

| 变量 | 含义 | V1 区间 |
|---|---|---|
| `NH3` | 氨氮（鱼排泄、残饵分解产生，高毒） | 0 - 危险阈值 |
| `NO2` | 亚硝酸盐（中毒） | 同上 |
| `NO3` | 硝酸盐（低毒，换水移除） | 累积 |
| `B1 / B2` | 两类硝化细菌生物量 | 0 - 环境容量 |
| `O2` | 溶氧量 | 受温度/灯/气泵影响 |
| `pH / TEMP` | 酸碱度/水温 | 装备调节 |

### 微分方程（简化因果模型）

```
d(NH3)/dt = 排泄源 + 残饵分解 − k1·B1·f(O2,TEMP)·NH3
d(NO2)/dt = k1·B1·f(...)·NH3 − k2·B2·f(O2,TEMP)·NO2
d(NO3)/dt = k2·B2·f(...)·NO2 − 换水移除（V2 加水草吸收）
dB1/dt   = 生长(NH3, 滤材表面积, O2, TEMP) − 衰减
dB2/dt   = 生长(NO2, 滤材表面积, O2, TEMP) − 衰减
```

- `k1/k2` 为反应速率常数，`f(...)` 为环境适宜度函数（溶氧/温度偏离适宜区间时抑制细菌活性）。
- 滤材表面积由过滤器型号与滤材配置决定，直接决定细菌容量上限——**装备真实改变系统动力学**。
- 换水：按换水比例瞬时稀释 NH3/NO2/NO3，同时少量损失细菌生物量。

### 鱼的影响

- 排泄源与鱼的数量、体重、喂食量正相关；残饵按未食用比例进入分解池。
- 鱼承受的毒性压力：`toxicLoad = w1·NH3 + w2·NO2`，作用于压力值与健康值；`O2` 不足、`TEMP` 偏离适宜区间同样加压。

### 数值实现

- 积分：显式方法在固定 1 秒步长下足够稳定；对细菌增长加环境容量钳制，所有变量做非负与上下限钳制。
- 全部速率常数集中在 `shared/balance/` 配置表，调参不改代码，Vitest 对基准场景做回归（开缸养水曲线、污染事故曲线）。

## 四、鱼的行为状态机

```
正常（群游/觅食） ── 饥饿/压力升高 ── 焦躁（游动加速/上浮）
      ▲                                  │
      └──── 环境恢复/喂食 ───────────────┘
压力持续 ──→ 疾病（厌食/躲藏）── 持续未干预 ──→ 死亡（小概率、强提示）
```

- 输入：饥饿度、toxicLoad、溶氧、温度、混养兼容性、惊扰事件。
- 输出：行为枚举（驱动渲染表现）、健康值、成长速率。
- V1 不做繁殖；成长按健康与进食累积体型参数。

## 五、装备参数模型

| 装备 | 关键参数 | 对引擎的作用 |
|---|---|---|
| 过滤器 | 流量、滤材表面积、细菌容量 | 决定 B1/B2 上限与净化速率 |
| 灯 | 亮度、色温、开关节律 | 昼夜节律、藻类增长、观赏 |
| 加热棒 | 目标温度、功率 | TEMP 趋近速率与维持 |
| 喂食 | 食物量 | 进食/残饵 → 排泄与 NH3 源 |
| 换水 | 比例 | 污染物稀释 |

装备以命令方式调整（`SetEquipmentCommand`），引擎校验合法性后生效并发事件，UI 不直接改引擎状态。

## 六、事件、快照与存档

- DomainEvent：`FishAdded / WaterChanged / ParameterWarning / BacteriaEstablished / FishSick …`，供 UI 提示、埋点、离线摘要使用。
- Snapshot：每 N tick 输出一份不可变快照（含全部状态变量与实体状态），Zustand 订阅；存档按时间间隔 + 关键事件双触发写 IndexedDB。
- 存档结构：`{ version, gameTime, worldState, eventLog, savedAt }`，带版本号支持后续迁移。

## 七、测试策略

- 单元测试：每个反应系统独立验证（如固定 B1 下 NH3 衰减符合预期）；
- 场景回归：
  1. 标准开缸：NH3 先升后降、NO2 跟进、最终 NO3 累积的经典曲线；
  2. 过喂事故：NH3 冲高触发警告，换水后恢复；
  3. 离线推演：与在线逐 tick 结果误差在容差内；
- 确定性测试：相同种子与命令序列，两次运行快照逐字段一致。

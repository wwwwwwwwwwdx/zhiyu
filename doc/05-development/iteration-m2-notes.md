# M2 迭代记录（一）：glTF 加载管线技术预研

状态：评审中
最后更新：2026-11-06

## 背景

M1 验收通过，进入 M2（内容与表现打磨）。按既定阶段策略，M2 才投入正式美术资产，第一批先做不依赖正式资产的 glTF 加载管线 Spike，验证"加载→替换占位→动画→失败降级"完整链路，为正式模型接入铺路。

## 本轮实现

### 模型加载封装（`src/render/ModelLoader.ts`）

- 封装 `GLTFLoader`，全渲染层共用一个实例；
- `loadModel(url)` 支持 http URL 与 data URI，失败统一转成可读错误，供调用方降级；
- `cloneModel` 支持同一资产被多个实例复用且互不影响。

### 程序化测试资产（`src/render/proceduralTestAsset.ts`）

- 用程序化几何体（身体锥体 + 尾鳍锥体）拼一条最小鱼；
- 通过 `GLTFExporter` 导出为 glTF data URI，全程不依赖外部正式美术资产。

### 渲染集成（`src/render/Renderer.ts`）

- 鱼对象类型由 `THREE.Mesh` 放宽为 `THREE.Object3D`，兼容 glTF Group；
- 新增 `setFishAsset(url)`：加载成功后设置模板并重建全部现有鱼，保留游动相位；失败时保留现有画面并返回原因；
- 新增鱼时优先克隆 glTF 模板，无模板则回退锥体占位；
- 统一 `disposeFishObject` 递归释放 glTF/占位的 geometry 与 material。

### 验证入口（`TankPage.tsx`）

- 日常操作区新增"切换 glTF 模型"按钮，触发程序化 glTF 的完整往返；
- 新增 `rendererRef` 暴露渲染实例，卸载时随 dispose 清空。

## 验证结果（均为实测）

- 生产构建：TypeScript strict + Vite 通过，53 模块（gzip 219.90 kB，体积因加入 Loader/Exporter 上涨，拆包在性能批次处理）；
- 浏览器实测：glTF 成功替换占位，截图可见两段式带尾鳍结构；新放的鱼复用模板、游动正常；
- 失败降级：坏 URL 加载被正确捕获（failed-as-expected），不破坏现有画面；
- 全过程控制台无错误。

## 第二批：性能基础设施

### 监控与画质档位（`src/render/PerformanceMonitor.ts`）

- `PerformanceMonitor` 按秒采样 FPS 与平均帧时间；
- 高/中/低三档画质预设，控制像素比上限（2/1.5/1）与粒子数、后期开关；
- 渲染循环按实测 FPS 自动降档，带滞后避免频繁切换；
- 暂停恢复保护：采样间隔远超正常周期（后台 rAF 被挂起）时本次不报数、重置基准，避免恢复瞬间误降档。

### 渲染集成（`Renderer.ts`）

- 新增 `setQuality / getQuality / getPerformance`，切换档位实时调整像素比并 resize；
- 页面隐藏时浏览器原生暂停 rAF，即天然后台降帧，无需额外轮询。

### 拆包（`vite.config.ts`）

- `manualChunks` 将业务代码、react 生态、three 拆为独立 chunk，改善缓存与并行加载；
- 构建产物：业务 110 kB（gzip 36.7）、react 162 kB（gzip 52.8）、three 521 kB（gzip 131.9）；
- 调高 chunkSizeWarningLimit 至 600，消除 three 独立 chunk 的固有体积误报。

### 测试

- 新增 `tests/performanceMonitor.test.ts`，覆盖 FPS 采样、暂停恢复保护、降档逻辑；
- 全量测试 3 个文件、19 个用例全部通过，生产构建通过。

### 测试环境限制（重要，如实记录）

- 自动化浏览器页面处于 `document.visibilityState = hidden`，浏览器对隐藏页暂停 rAF；
- 因此该环境无法实测动态 FPS 与游动（画面为静态帧），只能验证 DOM、逻辑与控制台；
- 真实前台可见环境下 rAF 与 FPS 监控正常，动态渲染需在可见浏览器中由人工或后续带可见上下文的自动化验证。

## 工程收敛：SAVE_VERSION 单一来源

- 问题：M1 时 `engine.ts` 内 `SAVE_VERSION` 与 `migrate.ts` 内 `CURRENT_SAVE_VERSION` 两处手写版本号，存在漂移风险。
- 收敛：在 `engine/core/types.ts` 定义唯一权威常量 `CURRENT_SAVE_VERSION`（与 `PersistedState` 类型同处），engine 写入与 migrate 迁移目标都引用它；删除其余两处本地定义。
- 依赖方向正确：persistence 本就依赖 engine 层，未引入反向依赖或循环依赖。
- 新增测试断言引擎写入版本等于权威常量，防止未来再次漂移；全量测试 22 用例通过，构建通过。

## 第五批：首条自制 glTF 鱼建模与接入

### 后台建模（`tools/blender/build_fish.py`）

- 用 Blender Python 程序化构建 `guppy`：椭球身体（长轴沿 X）+ 尾鳍（垂直扁平、尖端 -X）+ 一对侧鳍 + 一对眼睛；
- 脚本自动计算合并包围盒并居中到原点，导出 GLB；参数化 fish_id 与输出路径，后续鱼种可复用；
- 诊断输出：体长精确 0.600、中心对齐原点，导出 `public/models/fish/guppy.glb`（约 108 KB）。

### 接入与验证（`TankPage.tsx`）

- 经 `setFishAsset('/models/fish/guppy.glb')` 接入；
- 修复：最初模型只在手动点击按钮时加载，导致用户打开默认仍是锥体。改为页面初始化时**自动加载**默认模型，失败时渲染器内部降级为锥体并提示；
- 给 Renderer 增加 `isDisposed` 标志，异步加载在卸载后放弃后续操作，避免操作已释放资源；
- 浏览器实测：刷新后无需点击，4 条鱼自动显示为自制模型，glb 请求成功、无控制台错误，身体/尾鳍/眼睛结构与比例正确；
- 构建后 glb 已进入 `dist/models/fish/`，生产构建通过。

### 说明

- 仅完成 guppy 一种，其余 7 种鱼的资产可复用同一脚本批量化产出；
- 静态隐藏环境无法验证动态游动，但模型几何（嘴在 +X、尾鳍在 -X）与渲染 rotation 逻辑（t=0 时前向 +X 与速度方向一致）已形成闭环，无 M1 占位"倒着游"问题。

## 策略调整：建模后置，功能优先

- 评审首条程序化模型后，owner 认为视觉效果不达标，决定**现阶段先做功能、最后单独建模优化**；
- 已移除页面初始化时的 glb 自动加载，默认回到锥体占位；保留手动加载按钮作为后续验证入口；
- 该调整成本低：接入点 `setFishAsset` 与 Blender 管线已验证，待美术资产打磨完成后接入即可，功能代码无需改动。

## 依赖关系结论（无强依赖）

- 引擎层 `src/engine` 零 DOM、零渲染依赖，全部玩法（氮循环、鱼状态机、装备、经济、引导、存档、混养规则）都在引擎内，与美术完全解耦；
- 渲染层通过可插拔的 `setFishAsset` 消费模型，锥体是 fallback，因此"模型好坏"不影响任何功能推进；
- 鱼类数量/混养/行为差异属于引擎 catalog 与状态机逻辑，不依赖好看的模型；
- 唯一纯美术任务是任务6（正式资产），可独立排期、独立验收。

## 第七批：水草与 CO2 子系统（体现"生态缸"深度）

### 引擎层（`src/engine`）

- 新增类型 `PlantSpec`/`PlantState`，`WaterState` 增加溶解 `co2`，`EquipmentType` 增加 `co2`，`EquipmentState` 派生 `lightBrightness`/`co2Rate`；
- 新增 `PLANT_CATALOG`（水榕、蜈蚣草、莫丝），各自有 CO2/光照需求、成熟大小与 NO3 吸收能力；新增 CO2 装备 `co2-system`；
- 新化学模块 `src/engine/chemistry/plants.ts` `stepPlantLife`：CO2 注入与逸散、水草吸收 NO3（净化）与 CO2、开灯光合产氧/关灯呼吸耗氧、生长与健康、CO2 拉动 pH 下降；
- 新增命令 `buyPlant`（不强制硝化建立，幼苗从成熟大小两成长起），CO2 设备复用通用 `installEquipment`；CO2 超 2 触发警告。

### 数值稳定性修复

- 纯函数测试最初暴露：CO2 逸散用线性式 `co2 - k*co2*dt`，大 dt 单步会把 CO2 扣成负数清零，导致生长因子为 0；
- 改为指数衰减 `co2 * exp(-k*dt)`，对任意 dt 稳定，dt=1 时与原线性式几乎一致，不影响真实平衡。

### 存档升级与迁移

- `CURRENT_SAVE_VERSION` 升到 2，`PersistedState` 增加 `plants`/`plantSeq`（water.co2、installed.co2 随结构升级）；
- 首次启用迁移表，实现 1→2：补 `water.co2=0`、`plants=[]`、`installed.co2=null`、`plantSeq=0`，旧字段保留。

### 渲染与 UI

- `Renderer` 新增 `plantMeshes`，绿色圆锥占位、几何原点移到底部从砂面向上生长，随引擎 `size` 缩放，多株稳定分布；
- `TankPage` 新增水草店（3 个种植按钮），水质表增加 CO2 行（带状态灯），埋点新增 `buy_plant`。

### 验证

- 全量 6 文件、30 用例通过，生产构建通过；
- 浏览器内端到端（绕过 rAF 直接驱动引擎）：水草 0.1→0.5 生长、CO2 稳定 0.344、pH 6.83、光合产氧 8.25；v1→v2 迁移在浏览器内同样验证通过；

## 第八批：爆藻子系统（补齐 V1 承诺的因果联动）

### 背景

- PRD 明确"灯照过强过久→爆藻"，装备 catalog 注释也已暗示 brightness 影响藻类，但此前未实现；
- 藻类是真实水族高频问题，与已建的水草、光照、NO3 系统天然耦合，补齐后 V1 因果链更完整。

### 引擎层

- `WaterState` 新增 `algae`（藻类生物量）；
- 新增 `stepAlgae`（`src/engine/chemistry/plants.ts`）：光照暴露（开灯且亮度高）× 营养盐（NO3 越高越易爆发）×（1 − 水草竞争），净增长含基础死亡，无光照/低营养时自然消退；
- 水草茂盛通过竞争（化感与营养竞争）单向抑制藻类；algae 超 2 触发警告，提示减少光照或换水。

### 换水与迁移

- `diluteByWaterChange` 增加藻类物理清除（换水是除藻主要手段），并让 CO2 随换水稀释（修正此前遗漏）；
- 存档升 **v3**，迁移表新增 2→3：补 `water.algae=0`，其余字段保留。

### UI 与验证

- 水质表新增"藻类"行（带状态灯）；
- 全量 6 文件、34 用例通过，生产构建通过；
- 浏览器内确认 v3 模块健康：版本正确、algae 字段有界且 `Number.isFinite`、无运行时错误；爆藻因果（强光高 NO3 爆发、关灯消退、水草抑制）由纯函数单测精确验证；
- 排查中发现浏览器手动 import 会缓存 dev server 启动时的旧模块、不随 HMR 更新，硬刷新后恢复，后续浏览器验证需先刷新。

## 第九批：鱼寿命与年龄系统（补齐 V1 生物五要素）

### 背景

- PRD 规定鱼的状态含"饥饿度、压力、健康、成长、寿命"，此前缺寿命；
- 真实陪伴感来自生老病死，但为契合解压调性，自然死亡设计成温和、可预期、不频繁。

### 引擎层

- `FishState` 加 `age`（游戏秒），`FishSpec` 加 `lifespan`；
- 每 tick 累积年龄，进入寿命后段（80%）开始衰老、健康缓慢下降，越接近寿命越明显；
- 达到寿命触发"寿终正寝"并温和移除，与疾病/环境导致的"离开了"区分；新鱼 `age` 初始为 0。

### 数值设定

- 寿命按"游戏天"经 `GAME_DAY` 换算：小型鱼 550-650 游戏天，神仙鱼 900；
- 折合现实需连续运行约 9-15 天才会触发，V1 周期内仅重度常驻用户可能遇到，不频繁、不打扰。

### 迁移与验证

- 存档升 **v4**，迁移表新增 3→4：为已有鱼补 `age=0`；
- 全量 6 文件、36 用例通过，生产构建通过；
- 单测验证年龄按 tick 累积、接近寿命时寿终正寝并移除（通过构造高龄存档避免跑完整寿命）。

## 第十批：游戏化视觉重构（清透海洋）

### 背景与问题

- 用户反馈页面像专业软件/工具：右侧 330px 深色硬面板、密集表格与分隔线、浏览器原生灰色方角按钮、冷色警示灯、功能化文案、无动效，像做任务而非放松；
- 根因是信息密度高、UI 占据屏幕近三分之一，鱼缸沦为被管理对象。

### 设计系统（新增 `src/app/theme.css`）

- 确立"清透海洋"基调：浅青蓝主色、毛玻璃（backdrop-filter）、大圆角、柔和阴影；
- 定义统一变量与组件类：按钮体系（含图标按钮）、浮动操作坞、抽屉、卡片、状态点、事件时间线、toast，以及淡入/滑入/弹出等过渡动画；项目此前无任何 CSS 文件，此为首个全局样式。

## 第十一批：PRD 缺口补齐（气泡光影、视角交互、pH、数据导出）

### 自定义网格生成器（`tools/blender/build_fish.py`）

- `FISH_PARAMS` 集中 8 种鱼参数：8 个身体截面 (x, ry, rz)、尾鳍、背鳍、臀鳍、三色配色；
- `build_body` 沿 X 轴多截面 loft（14 环向段、首尾封口）形成纺锤鱼体；`build_symmetric_fin` 生成扁平尾鳍，`build_ranged_fin` 生成背鳍/臀鳍，胸鳍两侧旋转定位，眼睛位于头部两侧；

### 关键轴向错误的发现与修复

- 首次批量后用 `inspect_glb.py` 检查包围盒，发现神仙鱼 Z 宽度大于 Y，与"高身侧扁"预期相反；
- 经独立轴测试确认转换关系：Blender X→glTF X、Blender Z→glTF Y、Blender Y→glTF Z；
- 根因：脚本按 glTF 的 Y-up 写坐标（背腹放 Blender Y、左右放 Blender Z），但 Blender 是 Z-up，导出器再做一次 Z→Y 转换，导致背腹/左右互换；
- 修复全部 build 函数：身体顶点改为 (x, rz·cos, ry·sin)，各鳍展开方向改用 Blender Z，胸鳍/眼睛改到 Blender Y 两侧；修复后包围盒全部正确（神仙鱼 Y0.450>Z0.100，所有鱼侧扁）。

### Renderer 按鱼种加载与稀有着色

- `createFishMesh` 改为先按 specId 查模板克隆，其次单模板，否则锥体；新增 `applyVariantTint`，克隆材质并复制稀有颜色、保留模型形状；

## M2 视觉与商店体验修复（第二轮）

背景：owner 验收水草精修后提出四点问题——默认打开是斜角、背景是平面贴图旋转后露纯色、拖拽松手会自动回正、商店商品没有小图且像管理系统菜单。

### 决策

- 背景路线选**四面墙房间**（不扩成全景球、不做房间装修系统），保证 360° 环绕都有内容；
- 视角选**仅当次会话保留**，不写存档，刷新回默认正对；
- 装备**补做 glb 模型**，商店图标与缸内实体共用同一套模型，落实"所见即所得"；
- 商店图标全部由实际 3D 模型**离屏渲染**生成，不手绘图标（同类水族游戏 Fishdom、开心水族箱、《缸好有鱼》的商品图同样来自真实模型）。

### 视角（`CameraController.ts`）

- 初始相机 `(6,4,8)` → `(0,2.8,10)`，默认正对缸体，不再是斜角；
- 去掉 `baseAzimuth` 与 `AZIMUTH_LIMIT=±0.6rad` 的方位角夹取，方位角自由累积可 360° 环绕；polar 仍限 0.35~1.45 防翻转；
- `update` 不再用 sin 漂浮回正，始终使用当前 azimuth/polar，松手即停在当前角度；
- 测试改为按圆周角差比较（取模 2π 后取 `min(diff, 2π-diff) < 1e-5`），因为 `THREE.Spherical.theta` 归一化到 (-π,π]，直接比较累积 azimuth 会假失败。

### 四面墙房间（`Renderer.applyEnvironment`）

- 四个环境各新增左/右/后三个视角图（image_gen：写实、景深虚化、低饱和、无人物文字），命名 `{env}_{view}.jpg` 存 `public/backgrounds/`，正面沿用原 `{env}.jpg`，共 16 张（窗台前墙首版含人物已废弃重生成）；
- `makeWall` 按后墙（rotY 0、z=-14）、前墙（rotY π、z=+14）、左右墙（rotY ±π/2、x=±14）搭建，HALF_W/HALF_D=14、WALL_H=12、WALL_Y=1，并补地板（y=-5）与天花板（y=+7）防止俯仰穿帮；
- `getBackgroundTexture(id, view?)` 扩展视角参数，缓存 key 为 `id_view`；
- 地板由纯色 `0x9fb0b8` 改为程序化浅木纹（`getFloorTexture`：Canvas 画木条 + 细纹，重复 4×4，只创建一次复用），侧后视角不再出现大片空白地面。

### 装备建模（`tools/blender/build_equipment.py`）

- 基本体程序化建模 8 种装备：壁挂过滤器 60 / 外置滤桶 220 / 底滤系统 580 / 普通 LED 80 / 造景灯 260 / 50W 加热棒 45 / 100W 加热棒 95 / CO2 钢瓶 180；统一 6 材质参数签名（housing/housing2/metal/darkmetal/glass/glow），`transform_apply` 烘焙 → 归一化高度到 1 → 底部归零 → 导出；
- 配色由初版深色外壳改为浅灰蓝塑料（housing 0.34/0.47/0.53、housing2 0.50/0.63/0.69）：缸内水体与砂色都浅，深色装备在缸里会读成黑块；
- 壁挂过滤重做为"主体 + 顶部挂扣 + 下垂进水管 + 横向出水嘴 + 指示灯"；加热棒玻璃管改为不透明管身 + 金属帽（玻璃在浅水里几乎隐形），管径调粗到 0.075/0.09；
- `add_cyl` 增加 `rot` 参数，横向部件（出水嘴）可直接旋转烘焙。

### 商品图标（`src/render/IconRenderer.ts`）

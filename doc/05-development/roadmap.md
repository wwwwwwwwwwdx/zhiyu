# 产品路线图与里程碑

状态：评审中
最后更新：2026-11-05

## 总体节奏

先 Web 后小程序，先验证核心留存再扩内容与付费。所有里程碑以"可演示、可验证"为交付标准。

## 里程碑规划

### M0：立项与技术验证（第 1-2 周）

- 输出并评审产品愿景、PRD、架构方案；
- 渲染技术 Spike：Three.js 与 2D Canvas 方案各出一个鱼缸 Demo；
- 模拟引擎原型：氮循环最小模型跑通（氨氮/亚硝酸盐/硝酸盐随时间与滤材变化）；
- 出口标准：确定渲染路线，引擎原型可在浏览器中推演一条完整氮循环曲线。

### M1：核心循环可玩（第 3-6 周）

- 单缸场景、基础水体与光影、3-5 种鱼的游动与状态行为；
- 生态引擎接入：水质参数、鱼状态、喂食残余与污染联动；
- 基础装备：过滤器、加热棒、灯，参数真实作用于引擎；
- 本地存档与新手引导；
- 出口标准：内部可完整走通"开缸→养水→放鱼→喂食→换水"循环，无阻断性 Bug。

### M2：内容与表现打磨（第 7-9 周）

- 鱼类补齐至 5-8 种，混养兼容性与行为差异；
- 水质面板、状态灯、事件提示、离线回归摘要；
- 全屏/屏保模式、后台降帧、性能优化；
- 埋点接入与数据看板；
- 出口标准：达到灰度发布品质，关键性能指标达标（30 FPS+、兼容 Chromium 最新两版）。

### M3：灰度发布与验证（第 10-12 周）

- 小范围灰度（种子用户/技术社区），收集次留、7 留、时长数据；
- 依据数据快速迭代数值与引导；
- 短视频素材化能力（缸内画面一键录屏）；
- 出口标准：对照 PRD 验证指标（次留 ≥35%、7 留 ≥15%、单次时长 ≥8 分钟），决定是否进入 V2 与小程序立项。

## 后续版本方向（V1 验证通过后）

- V2：水草与造景、CO2 系统、繁殖选育、图鉴与成就、装备付费点；
- V3：小程序端（碎片化维护+社交分享）、账号体系与跨端同步；
- V4：海水礁岩缸、生态瓶、沉船打捞迷你游戏；
- 远期：助眠/屏保模式、轻社交（参观/互赠）、品牌化生态系列。

## 决策检查点

| 检查点 | 时间 | 决策内容 |
|---|---|---|
| 渲染路线定档 | M0 末 | Three.js vs 2D Canvas |
| 核心循环评审 | M1 末 | 玩法手感是否成立，是否继续投入 |
| 灰度 Go/No-Go | M2 末 | 性能与品质是否达到发布标准 |
| V2 立项 | M3 末 | 留存数据是否支撑扩展与付费设计 |
